# Ordering application visual consistency

The customer app is the visual reference. Its existing screen layouts, palette and typography remain the reference rather than being redesigned.

| Area | Finding and change |
| --- | --- |
| Typography | Admin/kitchen used Inter while customer/courier used Poppins. Both panels now load the matching Poppins weights. |
| Cards/navigation | Operations cards use the customer's rounded surfaces, subtle borders and no extra shadow. Active navigation uses the lime accent, with accessible current-page state. |
| Form controls | Panels use rounded fields and pill buttons with 44px minimum targets; visible keyboard focus is retained. |
| Role context | Kitchen header identifies the signed-in restaurant, useful when operating multiple restaurant accounts. |
| Secondary actions | Low-contrast lime text on light secondary buttons is replaced with the foreground token. |
| Shared components | Tailwind did not reliably scan shared chat/proof/notification sources. All four apps now explicitly include those sources, so their intended layouts and states are generated. |
| Courier primary actions | An unlayered `button { color: inherit }` overrode the primary foreground colour. The base rule now belongs to the base cascade layer, allowing the dark text on lime buttons. |
| Delivery/chat/proof | Shared controls follow the same rounded surfaces, fields, disabled states and spacing. Signature canvas retains its white drawing surface. |
| Menu management | Category names replace database IDs; editing and visibility actions are explicit. |

Customer/courier retain their mobile layout. Admin and kitchen keep denser desktop layouts for operations and are also checked at a 390px viewport for horizontal overflow. Both palettes remain supported; light operation screens are not a separate brand.

Visual evidence is generated by the card/cash delivery browser suite and the admin menu suite in `.qa/ui/`. Browser flows exercise real forms and API requests with disposable users; Stripe browser checks are separate and explicitly use sandbox credentials.
